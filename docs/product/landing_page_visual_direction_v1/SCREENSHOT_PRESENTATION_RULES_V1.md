# Screenshot Presentation Rules V1

**Status:** How product screenshots must be presented on the landing page.  
**Date (UTC):** 2026-07-29  
**Parent:** Visual Direction V1  
**Related:** Evidence Readiness Capture Plan · Visual Narrative Screenshot Governance · Wireframe placeholders  

**This phase does not select or capture screenshots.**

---

## 1. Purpose of a screenshot

A screenshot may appear only to:

- Explain a nearby claim  
- Build trust  
- Reduce uncertainty  
- Show recognisable CartFlow product truth  

If it only “looks premium,” it fails.

---

## 2. Hard rules

| Must | Must never |
|------|------------|
| Use current approved product UI | Use stale faces as current |
| Use demo/synthetic data only | Show real customer PII |
| Match the claim beside it | Decorate or fill space |
| Remain recognisable as CartFlow | Become wallpaper |
| Keep Arabic readable | Hide weakness via deceptive crop |
| Prefer one shot per section | Fabricate data or metrics |
| Keep native proportions on mobile shots | Exaggerate scale unrealistically |
| Scrub dev tools / harness chrome | Show test-only routes as product |

---

## 3. Role by evidence family

| Family | Presentation |
|--------|----------------|
| **Dashboard (LP-08)** | Dominates section; largest product visual on page; stillness preferred; device optional/minimal |
| **Widget (LP-06)** | Contextual in-store; prove storefront presence; **not settings** |
| **WhatsApp journey (LP-07)** | Journey/states; **not settings**; no Meta brand theatre |
| **Knowledge (LP-09)** | Card readable; evidence/insufficient state visible; no fabricated findings |
| **Hero preview** | Restrained; subordinate to headline; optional |

---

## 4. Framing rules

| Element | Rule |
|---------|------|
| Browser chrome | Keep only when it proves storefront context; otherwise omit |
| Phone frame | Matte, quiet, correct aspect; never larger in memory than UI |
| Laptop frame | Optional for dashboard; content-first |
| Padding around shot | Generous; do not collide with competing cards |
| Background behind shot | Calm; no busy patterns stealing edges |

---

## 5. Crop & zoom rules

| Allowed | Forbidden |
|---------|-----------|
| Crop to remove irrelevant chrome (nav noise, unrelated panels) | Crop that hides empty/insufficient honesty when the claim is about understanding |
| Mild focus crop on attention object if claim is attention | Zoom that invents a UI that doesn’t exist |
| Consistent safe margins | Different zoom languages per section without reason |

**Truth test:** A merchant who later logs in should recognise the same product.

---

## 6. Annotation style

| Allowed | Forbidden |
|---------|-----------|
| One short outcome caption outside the UI | Fake toasts, badges, or metrics drawn on the screenshot |
| Calm callout to a real UI region (rare) | Arrows/confetti/“+127%” stickers |
| “Illustrative” label when required by Evidence Readiness | Annotations that invent states |

Annotations must never become more memorable than the UI.

---

## 7. Shadow & elevation

- One soft elevation treatment for all primary screenshots.  
- No stacked neon glows.  
- No ground-contact “product photography” drama that fights Arabic UI readability.  

---

## 8. Corner radius consistency

- All product screenshots share one radius family.  
- Device frames share one radius family.  
- Do not mix sharp marketing cards with heavily rounded fake phones inconsistently.  

---

## 9. Multi-screenshot rules

- **Default:** one Hero screenshot per evidence section.  
- Second image only if it is a true Evidence Object state (e.g. insufficient) clearly secondary.  
- **Forbidden:** collages, 2×2 walls, before/after fake growth pairs.  

---

## 10. Eligibility reminder

Presentation rules do not override Evidence Readiness:

- Settings crops remain **ineligible** for Widget/WA journey heroes.  
- Knowledge themes remain RV-gated.  
- Placeholders in Wireframe ≠ approved captures.
