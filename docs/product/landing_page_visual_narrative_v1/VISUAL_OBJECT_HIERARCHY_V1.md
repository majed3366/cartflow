# Visual Object Hierarchy V1

**Status:** Binding hierarchy for landing visual narrative.  
**Date (UTC):** 2026-07-29  
**Parent:** Landing Page Visual Narrative V1  

Lower levels may never outrank higher levels in attention, memorability, or motion budget.

---

## Level 1 — Hero Objects

**Product truth. They own attention.**

May include (when Evidence Readiness allows publication):

| Hero Object | Typical section | Notes |
|-------------|-----------------|-------|
| Dashboard / Home / Workspace UI | LP-08 | Strongest ops hero |
| In-store tool (widget) UI | LP-06 | First primary product hero |
| WhatsApp journey / conversation states | LP-07 | Continuation hero — not “WhatsApp brand” |
| Knowledge cards / findings with evidence state | LP-09 | Understanding hero; earns broader identity |

**Rules:**

- Exactly **one** Hero Object family per section when Evidence Weight is Primary.  
- Hero must remain recognisable without Atmosphere.  
- Settings UIs are **never** Level 1 for Widget or WhatsApp journey claims.  

---

## Level 2 — Evidence Objects

**Reinforce product truth.** They support the Hero; they do not replace it.

Examples:

- Merchant workflow fragments  
- Customer journey steps (as product states)  
- Purchase confirmation / suppression state  
- Attention / priority state  
- Customer return state  
- Operational recovery state  
- Insufficient-evidence / wait state  
- Confidence / evidence-status cues  

**Rules:**

- Must be truthful and current.  
- May appear beside or within the Hero Object.  
- Must not invent metrics.  
- Insufficient-evidence states are first-class Evidence Objects (trust).  

---

## Level 3 — Supporting Objects

**Frame evidence. Never replace it.**

Examples:

- Phone devices  
- Browser / storefront windows  
- Laptop / tablet bezels  
- Product cards used only as storefront context  
- Soft caption labels tied to the Hero  

**Rules:**

- Visual importance **below** the enclosed or adjacent Hero/Evidence.  
- If Supporting Object is more memorable than the UI, demote or remove.  
- Forbidden as sole content of an evidence section.  

---

## Level 4 — Atmosphere Objects

**Create feeling. Never explain the product.**

Examples:

- 3D objects (eligibility per Motion & Depth Governance)  
- Soft gradients / background shapes  
- Light / shadow / depth planes  

**Rules:**

- Must support a nearby Hero Object.  
- If Hero is removed, Atmosphere must lose purpose.  
- Never introduce claims, features, or “AI” metaphors.  
- Never the most memorable object on the section.  

---

## Level 5 — Navigation Objects

**Guide movement only.**

Examples:

- Primary / secondary buttons  
- Anchor links  
- Accordion indicators  
- Scroll/progress cues (if any; keep minimal)  

**Rules:**

- Calm CTA philosophy.  
- Must not become promotional spectacle.  
- Must not compete with Hero Objects in evidence sections.  

---

## Cross-level conflict resolution

| Conflict | Winner |
|----------|--------|
| Atmosphere vs Hero | Hero |
| Device frame vs screenshot | Screenshot |
| Motion vs readability | Readability |
| Illustration vs real product UI | Real product UI |
| Multiple screenshots | One Hero; others removed or deferred |
| Nav CTA vs Dashboard inspect | Dashboard during LP-08; CTA owns only LP-15 |
